Interruption and continuation

After inspection saves cursor 1, the qualification process kills the Python server with SIGKILL. A different Python process opens the same state directory. The browser reconnects to the same work ID, resumes remaining safe tools, and reads the review receipt. Each recorded tool effect occurs once.

Trust boundaries and practical limits

  • Inputs in the public demonstration are synthetic. No owner credentials or employer data are displayed.
  • Persistent state belongs to the runtime. Model text does not override the saved cursor or completed node result.
  • The Web server binds to loopback, validates its Host header, and rejects cross-origin browser mutations.
  • Production deployment needs a verified cloud identity, authorized resources, authenticated user access, and an appropriate durable state service.
  • The process test kills after cursor publication. It does not prove atomicity inside an external distributed side effect or concurrent multi-writer execution.
  • Hash-linked evidence establishes integrity within the recorded chain; it is not independent third-party attestation.
  • The recorded display segment is continuous X11 capture. It is a qualification segment, not the final competition video.

Public reproducibility

The Public source replay workflow installs a fresh Python environment, checks dependencies, runs deterministic, SDK-tool and Web/API tests, executes the README workflow, and verifies a real process interruption.

The Browser and real display qualification workflow starts the actual application, drives Chromium, records the display with FFmpeg, and stores the raw segment, manifest, receipt, and this architecture PDF in a separate evidence branch.
